# AppleSupport AI Support Agent — Hiver SDE Intern Take-Home

An AI agent for the `AppleSupport` Twitter support account that:
1. Classifies each incoming customer message into one of 11 intents.
2. Drafts a reply grounded in how AppleSupport has historically resolved similar issues (TF-IDF retrieval over real past threads).
3. Decides `auto` vs `escalate`, with a stated reason.

## How to reproduce (under 15 minutes)

1. Open `Hiver_SDE_Intern_Simple_Pipeline.ipynb` in Google Colab.
2. Run **Section 0**: installs dependencies, then prompts you to paste your Gemini API key (get one free at https://aistudio.google.com/apikey). Nothing is hard-coded or committed.
3. Run **Sections 1–3**: downloads the Kaggle dataset via `kagglehub` (first run may ask for Kaggle auth), pairs customer↔AppleSupport tweets, cleans text, defines the intent taxonomy.
4. Run **Section 4** once: it writes `golden_set_to_label.csv`. Open it, fill in `true_intent` and `expected_action` for 150–250 rows, save as `golden_set_labeled.csv`, upload it back into the Colab session, then re-run Section 4 — it will load your labels.
5. Run **Sections 5 onward**: baselines, the Gemini agent, evaluation, LLM-judge, failure analysis, saved artifacts, and a live Gradio demo cell at the end.

Everything after your one-time hand-labeling (step 4) reruns in a few minutes on the default 4,000-row subsample — well inside the 15-minute budget the assignment asks for.

## Design choices (short version — full list in `decision_log.md`)

- **No neural network training.** Gemini does the classification, reply drafting, and judging directly; TF-IDF+LogisticRegression is kept only as the required "simple baseline," not as the main model. This keeps the pipeline fast, reproducible, and easy to explain live.
- **Golden set is the only ground truth used for headline numbers.** Both baselines are fit on a 70% slice of the golden set itself (not on weak/LLM-generated labels) and evaluated on the untouched 30% slice, so the comparison is apples-to-apples and never leaks into what's being measured.
- **Retrieval corpus is built from a separate working subsample of real historical AppleSupport threads**, never from the golden set, to avoid grounding replies on the same examples used for evaluation.
- **Auto/escalate is decided by the LLM with a stated reason**, using explicit escalation triggers (account/security, data loss, safety, billing/legal, low confidence) rather than a black-box threshold.

## Known limitations (see `report.md` for the full "what's misleading about my headline number" section)

- Golden test slice is small (~60 rows after the 70/30 split of a 200-row golden set) — expect high variance.
- Single brand, single language, single point in time — results won't automatically generalize.
- LLM-as-judge is a proxy for human review, not a replacement for it; a human-agreement check is included but only on a small sample.
